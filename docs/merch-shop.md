## Existing implementation and decisions

The previous `merch.html` / `merch.js` contained seven explicitly working SVG
placeholders (Tee, Hoodie, Cap, Stickers, Key Strap, Poster). No verified prices,
inventory, cart, order storage or order-submission endpoint existed. The action
opened an expression-of-interest email to `united@e36united.cz`. Those placeholder
sizes/material descriptions cannot establish specifications for these new garments.

This replaces that preview, not the Member Portal, event registration or LIVE.
`initUnitedAuth`, the Firebase session and authoritative `/api/united-club` read
are retained. Points/reward thresholds are unchanged. No Member rating is shown,
no percentage discount is invented, and no points are consumed by checkout.

## Implementation boundaries

- `merch/shop.js`: catalog, filters, text-labeled colors, native accessible
  dialogs, direct product/variant URL, Back/Escape/focus restoration, image
  thumbnails/zoom and horizontal swipe; cart/contact/review stages.
- `merch/cart.js`: versioned local cart; only variant ID, size, quantity persist;
  identical combinations merge; all lines are repriced from current catalog.
  Retired/unknown or incomplete variants block checkout and remain removable.
- `merch/order.js`: pure draft builder and separate email transport. Snapshot
  line prices/names, optional member UID, separate order/payment status, nullable
  order ID and payment reference are future extension points, not fake records.
- Contact name/email are prefilled from Firebase when available, not guessed
  from event participation. Contact/notes are memory-only and cleared when UID
  changes. No event registration or check-in is required. Existing public Merch
  guest access is preserved. Sign-in/navigation never discards cart contents.
- Opening email is **not** confirmation: UI explicitly requires the member to
  send it in their own client; cart/form remain intact. Clipboard fallback has a
  selectable text fallback if access is denied. No order API, email service,
  payment, QR, bank details, migration, or dummy “My orders” navigation added.
- Exact old recipient retained: `united@e36united.cz`. No messages sent in tests.
- Existing light/dark/system appearance and footer control preserved. New CSS
  is scoped to Merch. Existing public/shared theme files are not changed.
- Only Merch entry/new module links use `20260923-merch1`; shared cache tokens
  retain their current release. No Worker, API, D1, R2 or production data change.
